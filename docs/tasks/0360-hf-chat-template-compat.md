# Render Hugging Face chat templates as transformers does

**Problem.** The largest real use of Jinja in C++ is rendering a model's `chat_template`
per request in inference servers (0119). Those templates are written for transformers'
sandboxed environment, which adds what plain Jinja2 lacks: the `raise_exception(msg)`
and `strftime_now(fmt)` globals, and its own `tojson(x, ensure_ascii=False, indent=None,
separators=None, sort_keys=False)` that keeps key order and does not HTML-escape, unlike
Jinja2's `tojson` (sorted keys, htmlsafe). Jinja2C++ has neither global, and its `tojson`
takes only `indent`, so a template that calls these fails or renders differently. That is why
llama.cpp ships its own engine (minja), not Jinja2C++.

**Proposal.**
- A collection of real chat templates in `test/chat_templates/` (Llama 3.x, Qwen 2.5/3,
  Mistral, DeepSeek, Gemma, Phi, Command-R, including tool-call and reasoning variants),
  each with conversations and the output transformers renders, generated by a pinned
  script like the parity corpus.
- An opt-in environment preset (or documented globals) that provides `raise_exception`,
  `strftime_now` with an injectable clock for tests, and the transformers `tojson`
  signature. Plain Jinja2 behaviour stays the default. Whether the preset is public API
  or a documented recipe is a decision for `docs/api-2.0.md`.
- Fix every other difference the collection finds, or file it.

**Done when.** Every template in the collection renders byte-identical to transformers
for every conversation, in narrow and wide mode, and a CI job checks it. The rendering
times are added to the bench as cases next to `chat_llama`.

**Next.** 0355 checks the same templates through the Python module; share the collection.

## Progress

**Phase 1: the collection (test files only).** `test/chat_templates/`: 72 templates from
llama.cpp's `models/templates/` (the Hub is not reachable from the cloud runners), 10
conversations plus 2 template-specific ones, expectations from transformers 5.22.1's own
`_compile_jinja_template` under Python 3.12 (`generate.py --check` in the parity-expectations
workflow), and a gtest suite, narrow and wide, `ctest -R chat_templates`. 722 renders per mode.

With the public API alone (trim/lstrip blocks, loop controls, `raise_exception` and
`strftime_now` as globals, Jinja2's `tojson`), 582 of 722 renders match. The 140 others are in
`test/chat_templates/divergences.txt`:
- 0360 transformers `tojson` (keys in insertion order, no HTML escaping, `ensure_ascii`,
  `indent`, `separators`, `sort_keys`): most lines. A test-side transformers `tojson` (probe,
  added with `AddFilter`) clears all of them.
- 0360 `{% generation %}`: IFM-K2-Horizon, LFM2.5-8B-A1B, LFM3 and the three poolside Laguna
  templates do not load.
- 0360 transformers' `ImmutableSandboxedEnvironment` rejects `list.append`: Kimi-K2-Instruct
  and Kimi-K2-Thinking with tools; Jinja2C++ renders.
- 0297 `"x" in none` is a TypeError: gpt-oss and llm-jp with string tool-call arguments.

**Phase 2: the preset** (decided by Ruslan 2026-11-01, docs/api-2.0.md 3.3 and 7.8).
`jinja2cpp/chat_template.h`: `ConfigureForChatTemplates(TemplateEnv&, ChatTemplateOptions)`,
behind the CMake option `JINJA2CPP_WITH_CHAT_TEMPLATES` (default ON; `JINJA2CPP_HAS_CHAT_TEMPLATES`
and `JINJA2CPP_CHAT_TEMPLATES_TRANSFORMERS` in the generated `jinja2cpp/features.h`, included by
`config.h`). It sets trim/lstrip blocks, loop controls, autoescape off and `maxRange` at most
100000, adds `raise_exception` and `strftime_now` (injectable clock), and switches the
environment's internal dialect (`src/dialect.h`, kept in `LoadSettings` like the big-int backend):
transformers' `tojson` (a `Serialize` mode chosen at parse time), the `{% generation %}` tag (a
scope like `{% with %}`; `break` does not cross it, as in transformers' call block) and read-only
lists and dicts (the mutating methods are the sandbox's unsafe attributes). The dialect code is
always in the core and dormant otherwise. All 722 renders match in narrow and wide mode;
`divergences.txt` is empty. Bench cases `hf_qwen3`, `hf_gpt_oss`, `hf_deepseek_v31` and
`hf_mistral_small` render real templates next to `chat_llama`. Follow-up: 0377 (assistant token
mask, SecurityError code).
