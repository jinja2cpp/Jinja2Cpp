# A user-facing benchmark and feature-parity comparison with rival engines

**Problem.** Someone who finds Jinja2C++ and compares it with other engines has nothing
to read. The numbers exist only as internal notes: `bench/run.py --engines` measures
Jinja2C++ against Python Jinja2, MiniJinja, Tera, minja and inja
(`/mnt/project-files/perf-track/2026-10-12-engines.md`: Render faster than MiniJinja on
every case, Load within 0.84-1.0x of it on small templates). Feature coverage is in
`docs/parity.md` for Jinja2C++ alone. Ruslan (2026-10-18) wants a report that "sells
Jinja2C++" to someone comparing implementations, before 2.0.

**Proposal.**
- **Performance:** one generated page per release with Load and Render per case and
  engine, the ratio to Jinja2C++, the hardware, versions and commit, and how to rerun it
  (`bench/run.py`). Cases come from 0247's coverage of the rivals' own suites.
  Instruction counts or medians of repeated runs; noise stated.
- **Features:** run the parity corpus (`test/parity/cases/`) through each rival engine
  that has a driver, and report per area how many cases each renders identically to
  Python Jinja2. This turns "we have 1886/1929" into a comparable number.
- **Honest framing:** list where a rival wins and why. Each engine runs at its own
  current release, configured as its documentation recommends.
- Generated by a script (`bench/report.py`) in CI on tags and published on the website
  (0243's performance page links or embeds it), with a summary in the README.

**Done when.** The report is generated from one command, published for the 2.0 RC on the
site, covers every engine of `bench/` and every 0247 case, and includes the per-area
feature counts.
